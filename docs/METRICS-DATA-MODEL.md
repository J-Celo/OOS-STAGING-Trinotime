# Metrics data mapping and compatibility

Existing sources: workforceCoverage/v1/daily and workforceConfirmation/v1/daily contain submissions, measured completed-task active milliseconds/count, presence time and action counters. workforceTrackerShift/v1/current and sessions define Time In/Out identity and archive workflows. workforceMetrics/v1/targets holds date-effective POD/workflow targets. Reset audits already exist in workforceTrackerShift/v1/resets.

New projection: workforceMetrics/v2/shifts/{actorKey}/{padded-start-ms}_{encoded-session-id}. One compact record per finalized shift, created conditionally with Firebase ETag. Includes actor/POD, session, generation, start/end, workflow metric rows and target snapshot. Full job/task archives remain under existing sessions paths. No destructive migration or schema replacement occurs.

GET /api/workforce/metrics/shifts accepts range=current|7|30, optional exact Agent name, optional Admin-only POD scope, and offset. Authorization resolves canonical visible Agents before any requested records. When Admin selects a POD, both the Agent list and current-shift aggregate are server-scoped to that authorized POD; the aggregate still covers the full selected POD independently from the ten-Agent visible roster page. Without a selected POD, the existing all-authorized-scope aggregate and per-POD comparison remain available. The aggregate uses compact current-shift and date-root reads with bounded exact reads for finalized immutable scorecards. History still requires one Agent and a Firebase $key query limited to 7/30 compact records; POD selection narrows which Agents can be chosen but does not redefine locked-history semantics. TL history additionally excludes prior PODs. Existing /dashboard date API remains compatible and now accepts the same Admin-only POD scope for date-report rows. /reset-audit binds Agent and session metadata before reading at most 20 audit records.

A=100%+, B=80%+, C=60%+, D=40%+, F below40%. Workflow efficiency = target seconds/task * measured tasks / measured active seconds *100. Overall efficiency sums earned target time and divides by total measured active time; it does not average percentages. Missing timing or target is ungraded. Only measured completed tasks contribute. Tracker counters and manual adjustments remain separate operational indicators.

Presence utilization is active/(active+focused idle+away), shown only with away telemetry. It is not part of the grade. Job-specific targets are the existing Coverage/Confirmation targets for each POD; no new arbitrary targets are created.

Review risks on staging: actual Time Out sync ordering remains the existing Tracker/attendance integration; immutable metrics freeze the server-acknowledged snapshot. Offline/unacknowledged client work is not guessed. Test final task submission then immediate Time Out on real Augmoto before acceptance.
